# CLAUDE.md

## Project

Golden Path — internal developer platform for GitHub Organizations. Provides reusable CI/CD workflows, automated repository onboarding, standardized profile templates, and release automation.

**Stack:** YAML workflows + plain `.mjs` scripts (zero runtime deps). Node 22, npm, ESLint flat config, Prettier, Husky, Commitlint.

## Architecture

See [docs/architecture.md](docs/architecture.md) for system overview, onboarding flow, and design principles.

## Scripts

All scripts are in `scripts/` — plain `.mjs` files, no TypeScript, no build step.

| Command                  | Purpose                             |
| ------------------------ | ----------------------------------- |
| `npm test`               | Run 42 tests via `node --test`      |
| `npm run lint`           | ESLint on scripts/                  |
| `npm run format`         | Prettier write                      |
| `npm run format:check`   | Prettier check                      |
| `npm run lint:workflows` | actionlint workflows (needs binary) |

## Pull Requests

Follow [.github/PULL_REQUEST_TEMPLATE.md](.github/PULL_REQUEST_TEMPLATE.md) when creating PRs. Checklist includes test, lint, format, and workflow validation.

## Git Hooks

- **pre-commit**: main branch guard → format check → lint → tests (42 must pass)
- **commit-msg**: conventional commits via commitlint (`feat:`, `fix:`, `chore:`, `docs:`, `refactor:`, etc.)
- **No direct commits to `main`** — always use feature branches

## Workflows

All reusable workflows live in `.github/workflows/`. Every script is consumed by at least one workflow (zero dead code).

### Architecture

- **Workflows** = pure YAML orchestration (`actions/github-script` blocks ≤ 10 lines each)
- **Scripts** = encapsulated business logic (single-purpose `.mjs` files with JSDoc)
- **Shared helpers** = `scripts/lib/` (gh.mjs, fs.mjs, profile-map.mjs)

### Key Workflows

| Workflow                      | Type                 | Purpose                                       |
| ----------------------------- | -------------------- | --------------------------------------------- |
| `self-ci.yml`                 | Triggered + reusable | Lint, test, format, actionlint, secret-scan   |
| `release-github.yml`          | Reusable             | GitHub Release (tag-driven or release-please) |
| `release-npm.yml`             | Reusable             | npm publish                                   |
| `release-github-npm.yml`      | Reusable             | GitHub Release → npm publish                  |
| `build-test-node.yml`         | Reusable             | Node.js CI (lint → typecheck → test → build)  |
| `build-test-go.yml`           | Reusable             | Go CI (lint → vet → test → build)             |
| `codespell.yml`               | Reusable             | Spell check                                   |
| `secret-scan-betterleaks.yml` | Reusable             | Secret scanning                               |
| `actionlint.yml`              | Reusable             | Workflow linting                              |
| `repository-onboarding.yml`   | Triggered            | Issue → validate → config → PR                |
| `apply-repository-config.yml` | Triggered            | Profile merge → PR into target repo           |

## Engineering Conventions

- **No dead code** — every script imported by a workflow, every function exported is tested
- **No TypeScript** — plain `.mjs` with JSDoc
- **Zero runtime deps** — scripts use only Node.js stdlib + `gh` CLI
- **DRY** — 3 shared lib helpers (gh, fs, profile-map), no duplicated logic
- **Idempotent** — onboarding and config application safe to re-run
- **Never overwrite silently** — conflicts flagged for manual review
- **Exact versions** — `.npmrc` has `save-exact=true`
- **Timeouts** — all CI jobs have `timeout-minutes`
- **GitHub Actions bot identity** — all automated PRs attributed to `github-actions[bot]`
