# CLAUDE.md

## Project

Golden Path — internal developer platform for GitHub Organizations. Provides reusable CI/CD workflows, automated repository onboarding, standardized profile templates, and release automation.

**Stack:** YAML workflows + TypeScript actions (bundled with esbuild) + plain `.mjs` scripts (zero runtime deps). Node 22, pnpm workspaces, Vitest, ESLint flat config (eslint 9), Prettier, Husky, Commitlint.

## Architecture

See [docs/architecture.md](docs/architecture.md) for system overview, onboarding flow, and design principles.

## Package Manager

This is a **pnpm workspace** monorepo. Use `pnpm` (never `npm`):

- `pnpm install` / `pnpm install --frozen-lockfile`
- `pnpm add <pkg>` for a specific workspace package (`pnpm --filter @golden-path/action-parse-config add ...`)
- `pnpm -r <script>` to run a script across all workspace packages (topological order)
- `@golden-path/core` is consumed via `workspace:*` and bundled into each action at build time

## Scripts

Scripts in `scripts/` are plain `.mjs` — no TypeScript, no build step. Action logic lives in `packages/actions/*/src` as TypeScript.

| Command                   | Purpose                                    |
| ------------------------- | ------------------------------------------ |
| `pnpm test`               | Vitest (actions) + `node --test` (scripts) |
| `pnpm test:actions`       | Vitest for TS packages                     |
| `pnpm test:scripts`       | `node --test` for scripts/                 |
| `pnpm typecheck`          | `tsc --noEmit` across TS packages          |
| `pnpm run lint`           | ESLint on scripts/ + packages/             |
| `pnpm run build:actions`  | esbuild bundle actions to committed dist/  |
| `pnpm run format`         | Prettier write                             |
| `pnpm run format:check`   | Prettier check                             |
| `pnpm run lint:workflows` | actionlint workflows (needs binary)        |

## Pull Requests

Follow [.github/PULL_REQUEST_TEMPLATE.md](.github/PULL_REQUEST_TEMPLATE.md) when creating PRs. Checklist includes test, lint, format, typecheck, and workflow validation.

## Git Hooks

- **pre-commit**: main branch guard → format check → lint → typecheck → tests
- **commit-msg**: conventional commits via commitlint (`feat:`, `fix:`, `chore:`, `docs:`, `refactor:`, etc.)
- **No direct commits to `main`** — always use feature branches

## Workflows

All reusable workflows live in `.github/workflows/`. Every script is consumed by at least one workflow (zero dead code).

### Architecture

- **Workflows** = pure YAML orchestration (`actions/github-script` blocks ≤ 10 lines each)
- **Actions** = TypeScript, bundled to a committed `dist/index.cjs` (real JavaScript actions, `using: node20`)
- **Scripts** = encapsulated business logic (single-purpose `.mjs` files with JSDoc)
- **Shared helpers** = `packages/core/src` (config parse/normalize, injectable `exec`) + `scripts/lib/` (gh.mjs, fs.mjs, profile-map.mjs)

### TypeScript Actions

All action logic lives in `packages/actions/<name>/src`:

- `action.ts` — pure, fully unit-tested logic (no `@actions/core` imports)
- `index.ts` — thin `main()` glue: `getInput` → call `action.ts` → `setOutput` / `setFailed`
- `src/__tests__/` — Vitest tests covering the pure logic

Shared logic (config schema, injectable `exec` runner) lives in `packages/core/src` and is imported by actions via `@golden-path/core`.

After changing any action source or its dependencies, run `pnpm run build:actions` and **commit the rebuilt bundle** — consumers never run `npm install`. CI enforces this with a `git diff --exit-code` check on `.github/actions/`.

## Engineering Conventions

- **No dead code** — every action is consumed by a workflow, every exported function is tested
- **TypeScript for actions, plain `.mjs` for scripts** — actions get full typing; onboarding scripts stay dependency-light
- **Zero runtime deps for scripts** — `scripts/` uses only Node.js stdlib + `gh` CLI. Actions bundle their deps into `dist/index.cjs` via `pnpm run build:actions`
- **DRY** — shared helpers in `packages/core` (config, exec) and `scripts/lib` (gh, fs, profile-map); no duplicated logic
- **Idempotent** — onboarding and config application safe to re-run
- **Never overwrite silently** — conflicts flagged for manual review
- **Exact versions** — `.npmrc` has `save-exact=true`
- **Timeouts** — every job must have `timeout-minutes: 15`
- **GitHub Actions bot identity** — all automated PRs attributed to `github-actions[bot]`
- **Workflow naming** — inputs: `kebab-case`, outputs: `snake_case`, secrets: `UPPER_SNAKE_CASE`. Reusable workflows with outputs MUST declare `on.workflow_call.outputs`. Boolean outputs use `is_` prefix.
