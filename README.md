# Golden Path

Internal developer platform — standardized, reusable CI/CD workflows, automated repository onboarding, and org-wide profile templates.

## What It Does

| Layer                  | What                    | How                                                                                     |
| ---------------------- | ----------------------- | --------------------------------------------------------------------------------------- |
| **Reusable Workflows** | Standardized CI/CD      | One `uses:` line in any repo gets lint, test, build, security scan, release, and deploy |
| **Onboarding System**  | Self-service repo setup | Open an issue with a form → config generated → PR created → standard files applied      |
| **Profile Templates**  | Shared config files     | `.editorconfig`, `CODEOWNERS`, `SECURITY.md`, linters, Dockerfiles — all standardized   |

## Quickstart

```bash
# Clone
git clone https://github.com/your-org/golden-path.git
cd golden-path

# Install (only eslint + prettier for script linting)
pnpm install

# Run script tests
pnpm test

# Lint scripts
pnpm lint

# Lint workflows (requires actionlint)
pnpm lint:workflows
```

## Using Workflows

In any repo, create `.github/workflows/ci.yml`:

```yaml
name: CI
on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  build-test:
    uses: your-org/golden-path/.github/workflows/build-test-node.yml@main
    secrets: inherit

  security:
    uses: your-org/golden-path/.github/workflows/security-scan.yml@main
    with:
      language: node
    secrets: inherit
```

## Onboarding a Repository

1. Go to **Issues** → **New Issue** → **Repository Onboarding**
2. Fill in: repository name, type, language, optional features
3. Submit — a PR is automatically created adding the config
4. Once merged, the standard configuration is applied to your repo

## Repository Structure

```
golden-path/
├── .github/
│   ├── workflows/          # 9 reusable + onboarding CI workflows
│   └── ISSUE_TEMPLATE/     # Repository onboarding form
├── profiles/               # File templates (common, node-library, node-service, go-service)
├── repositories/           # Per-repo config (generated by onboarding)
├── scripts/                # Plain .mjs helper scripts (zero deps)
│   ├── lib/                # Shared helpers (profile-map.mjs)
│   └── test/               # Tests (node --test)
└── docs/                   # Architecture + guides
```

## Adding a New Language

1. Add the mapping to `scripts/lib/profile-map.mjs`
2. Create `profiles/<language>-<type>/` with the file templates
3. Update the issue form dropdowns in `.github/ISSUE_TEMPLATE/repository-onboarding.yml`
4. Keep the profile map in sync with `platform-observability`
